# Codex in Riot Bot

The preview connector uses the official Codex CLI’s app-server and its managed ChatGPT sign-in. Codex owns the native agent loop, context compaction, streaming, tools, and web search. Riot Bot supplies the bot’s identity, memories, chat history, skills, attachments, task timer, approval UI, and activity record. API backends continue using Riot Bot’s existing tools and free Brave browser search.

## Connect

1. Install the official Codex CLI if it is missing, then restart Riot Bot. The connector was checked against Codex CLI **0.154.0** on November 2, 2026.
2. In **Settings → Connections & default model**, choose **ChatGPT account**.
3. Click **Sign in with ChatGPT** and finish the official browser flow. Riot Bot opens only the supported HTTPS authentication hosts. **Cancel sign-in**, **Refresh connection**, and **Disconnect Codex** (under **About this connection**) are available in the same panel.
4. Choose a Codex model from the connected account’s picker. **New bot → Connection & model** uses the same picker and loads the catalog when Codex is selected. An old model choice remains visible for correction. Riot Bot pauses an unlisted model before starting a native turn; being listed still does not guarantee that the account can use it.
5. Save app settings. For an existing bot, open **Bot settings → Model → Use app default**, then save. Choose its working folder in **Bot settings → Files & tools**. Send a message to start a native turn.

Sign-in and status checks do not start a model turn. Riot Bot neither imports another app’s login nor copies tokens out of your normal Codex profile. The connection is app-wide; each bot still has its own native conversation mapping.

## Usage and tools

Native turns use the signed-in account’s Codex allowance and any additional usage settings enabled for that account. Riot Bot displays reported usage percentages and reset times when supplied. Unknown usage remains unknown. Activity records native turn attempts and reported token counts separately from API dollars. API call counts, output-token limits, context fitting, and dollar ceilings do not control the native agent loop. Task minutes and Stop do apply.

An authentication error, quota failure, failed turn, or disconnected server pauses/fails visibly. Riot Bot never silently switches provider, account, model, or API key. Saved [bot-task schedules](scheduling.md) can start native turns while Riot Bot is running; missed turns wait for **Run now**. Interrupted actions are not retried automatically.

With tools enabled, Codex retains native web search, shell, and file capabilities. Prefixed `riot_` tools expose this bot’s memories, bounded history/attachments, skills, reactions, bounded workspace reads, static website verification, built-in schedules, and Riot Bot web search. `riot_web_search` and `riot_fetch_url` use the shared Settings → Web search choice: keyless Tavily, one Firecrawl fallback, a saved connection, or the browser. They count toward that bot’s 40 daily research requests, and in account mode toward the account cap as well. A connection check counts too. Native built-in search remains available and follows Codex's own rules. The Web search setting and those counters do not govern that built-in search. Riot Bot also exposes its browser and saved-login tools so native bots can use the same persistent site sessions and locally filled passwords; these tools obey Riot Bot's per-site permissions. `riot_page_screenshot` is left out, because Codex tool results are text only. `riot_run_on_server` runs an approved command on a saved server through PuTTY’s plink with Riot Bot’s approval card, so the password never reaches Codex. Riot Bot does not add an API shell tool alongside the native shell. Turning off the native shell/search/Riot Bot tools checkbox disables those capabilities and forces a read-only policy; other built-in native capabilities are governed by Codex. Unsupported native permission/forms requests are declined. Ask/answer clarifications through ordinary chat.

Codex’s built-in search source is not a verified Google organic position. Exact rank claims still require observed results from the named engine in the browser. A native built-in search does not use Riot Bot’s visible browser profile, its CAPTCHA handoff, or the Tavily/Firecrawl setting. `riot_web_search` follows that setting and also is not a Google position.

Gmail tools use Riot Bot’s own mailbox connection and send path. `riot_gmail_send_draft` cannot approve itself. It waits for the complete-message review unless a reply rule already turned on for this bot matches the exact reply, recipients who were already mailboxes in that conversation, and an original message whose plain-text and HTML versions can still be read and match. Native Codex cannot widen that rule. See [Gmail](gmail.md#what-this-bot-can-do-on-its-own).

Disk-space questions use `riot_get_disk_space`, a read-only capacity query in Riot Bot’s runtime. The default checks the filesystem containing this bot’s working folder; a path can select another local drive or folder. Results identify that scope, include a measurement timestamp, and distinguish byte counts from decimal GB. Riot Bot rejects network paths, mapped network drives and links into remote locations before the capacity query. A fixed noninteractive Windows helper classifies local drive roots; no model-provided command is executed and no command approval is needed. It avoids native sandbox language-mode restrictions without changing native permissions. Native sessions start a fresh scoped thread once when the tool-set version changes, with Riot Bot’s usual history bootstrap and search available.

## Permissions and sessions

The connector selects native `untrusted` approvals and read-only or workspace-write policy, never bypass mode. Safe read commands can run automatically under Codex’s rules. Native command/file requests that need approval appear in Riot Bot; approval applies once. Network and additional filesystem permission requests are declined. Native file edits do not have Riot Bot’s Undo button.

On Windows, Riot Bot selects the unelevated native sandbox and requires its readiness check before a tool-enabled turn. Read-only writes, allowed workspace writes, and denied writes outside that workspace were checked directly against the installed CLI. The installed version’s legacy policy permits filesystem reads outside the workspace. Native sessions are logically separated by bot/conversation, but are not a confidentiality boundary for native filesystem reads. This differs from Riot Bot’s bounded API file tools and its separately approved, unsandboxed API terminal.

A completed native thread is resumed only for the same bot, conversation, connection identity, model, workspace, editing setting, and tool setting. A fresh thread gets a bounded recent-history excerpt and memory/skill context. Riot Bot does not resend the whole transcript into a resumed native thread. Stop, failed work, account changes, relevant configuration changes, and API turns invalidate reuse. Restart does not repeat unfinished work. Stop sends the native interrupt and closes the owned process tree if the server does not acknowledge promptly.

Riot Bot’s separate `CODEX_HOME` is `%APPDATA%\riot-bot\codex`. The official CLI manages its authentication storage there; Riot Bot’s Windows-encrypted API-key store is separate. Include the complete Codex profile in a private app-data backup after signing in. Source archives and Git checkpoints do not contain it.

## Verification

The installed CLI initialized, accepted a thread and dynamic-tool schema, and enforced the tested Windows write policies using a fresh signed-out profile. No model turn was started in that check. Protocol fixtures exercise managed login/cancel/logout, native search events, scoped Riot Bot memory, attachments, session reuse/restart, approval refusal, Stop (including a stuck child process), quota/disconnect errors, and separate usage accounting. A disposable Electron instance exercises the provider controls, authentication status events, chat, and Activity without renderer errors.

An authenticated acceptance task on November 2 used the connected Riot Bot account in an isolated profile with **gpt-5.6-sol**, selected explicitly after the account rejected the previously saved gpt-6.1-sol. It created an HTML page through approved native file edits, used Riot Bot’s website checker, repaired detected mobile overflow and returned a short summary with a file link. Library captured four output files. Independent checks of the final page passed both viewport sizes and the JavaScript button interaction. The task used no API calls or fallback. Earlier diagnostic attempts included the rejected model, a test approval-wait issue and declined file edits while approval display was being corrected; those attempts were not successful acceptance tasks. No native web-search quality claim is made by this local website task.

Protocol reference: [Codex App Server](https://learn.chatgpt.com/docs/app-server). The alternate registered [Sign in with ChatGPT integration](https://developers.openai.com/siwc/quickstart) is a different authentication route and is not implemented here.
