# Reminders and scheduled bot work

Use **Workspace → Schedule** for the selected bot, or ask in its ongoing Chat. API bots use `create_schedule`, `list_schedules` and `manage_schedule`; native Codex exposes their `riot_` equivalents. A request like “Check our email system for RLH every morning” should resolve the system and objective from that bot’s context, history and memories. The bot asks if the target, time or time zone is unclear. It confirms the next occurrence only after the schedule saves. Scheduling does not require creating scripts, terminal approvals or Windows tasks.

**Reminders** show their text in a Windows notification and an in-app banner, with a saved result in Schedule. They make no model call, even if no model is configured. Windows notification settings can suppress delivery; unsupported or failed delivery is noted in Schedule. Clicking a notification opens the owning bot’s Schedule screen. A missed reminder shows once when Riot resumes, rather than replaying every missed occurrence.

**Bot tasks** enter the existing durable task queue. Each run uses the owning bot’s current model, workspace, memory, history, tools, instructions and budget. It is independent of the bot currently selected in the window. The objective appears in Chat and results appear in Chat, Tasks and Files as usual. Commands and consequential browser actions keep their normal approvals. API spending limits still apply; native Codex runs use the connected account’s allowance and native approval rules. A schedule cannot grant access or create a connection. Scheduled work cannot create or modify schedules itself.

## Context and editing

When a bot task is saved, Riot keeps a redacted context excerpt: the conversation summary and user/assistant messages from the latest twelve messages, capped at 1,500 characters per message and 12,000 characters in total. The task instructions should state the actual objective, resolving references from the chat. That excerpt is reference material, not additional permissions. Current memories and searchable history can supply missing details or updates. There is no promise of perfect recall. **Saved conversation context** on the schedule card shows what was captured; passwords and API keys must stay out of task instructions.

The form supports once, daily, weekdays and weekly, using the computer’s IANA time zone for a new schedule. Chat can specify another IANA zone. Existing schedules retain their saved zone if the computer travels. Daily and weekly times follow the local clock across daylight-saving changes. A recurring time skipped by a clock change moves forward by the gap; a repeated clock time runs once that day. The form rejects a nonexistent initial clock time so the user can choose another.

Edit changes the objective and timing; an existing bot task keeps its captured context. Pause stops automatic occurrences. Resume computes the next future occurrence and does not replay missed work. Cancel stops future occurrences and retains the record under **Show cancelled schedules**. Edit or Resume can reuse it. A one-time date that has passed requires a new date or **Run now**. **Show now / Run now** explicitly triggers one occurrence; a future planned occurrence remains scheduled. Use Tasks to stop work already queued or running.

## Local execution and recovery

Riot must be open or in the tray, and the computer must be on and awake. There is no cloud scheduler, OS wake service, email delivery or mobile push. The main process checks due schedules every five seconds. Quit stops these checks and interrupts active jobs. Reopening shows overdue reminders, but overdue bot work is marked missed and waits for **Run now**. A future occurrence of a recurring schedule remains enabled. After sleep or a gap over 75 seconds, due AI tasks wait for manual catch-up; a task over one minute late also waits.

A queued or running occurrence, or one waiting for approval/recovery, blocks another occurrence of the same schedule. The skipped occurrence is noted instead of duplicating the work. A failed, paused or stopped run pauses that schedule for review. **Stop all work** also pauses active bot-task schedules, while reminders remain enabled. Interrupted queue items retain the existing explicit Resume policy.

Schedules and occurrence dispatch are persisted in SQLite schema version 11. Updating a due occurrence and creating its job happen in one transaction. A crash after reminder dispatch can prevent the native notification from appearing; the saved result remains available, and Riot does not replay a completed reminder. External work retains the queue’s review-based recovery policy, rather than an exactly-once guarantee. Identical active/paused save retries are deduplicated. A bot can retain up to 100 schedules, including cancelled records; edit an existing record to reuse it. Deleting a bot or its owning conversation removes its schedules. No existing Windows scheduled tasks are imported or changed.

The automated checks use disposable databases, fake providers and protocol fixtures. They cover calendar/DST changes, migration, isolation, context capture, normal budgets and approvals, overlapping occurrences, restart recovery, failure pausing, deduplication and native Codex tools. They do not contact an email system or create a real reminder on the user’s computer.
